## 1. 目标与边界

本方案在现有复盘中心之上增加一个可审计的大模型分析层，并把传统逻辑、大模型判断、市场环境和个人交易经验统一成最终分析结果。

当前实现边界：

- 不接入实盘下单；
- 模型与妙想密钥只写入 Git 忽略的 `llm_trade.local.yaml`；
- 妙想只读工具可在获取真实 `tools/list` 后进入白名单，自选写入需再次确认目标组，模拟/真实交易写工具固定禁用；
- 没有真实数据样本前不伪造模型升级门槛、最小样本量或最优融合权重。

已完成：OpenAI 兼容 Responses/JSON Schema Provider、双周期传统模型、个人知识检索、受限融合、价格/仓位计划、SQLite 观测与反馈、次日/5日路径标签、复盘中心用户勾选调用和三层结果展示。

预期目标：

1. 从配置读取 `url`、`sk`、`model` 等参数，支持 GPT、DeepSeek、Qwen 及其他 OpenAI 兼容服务。
2. 把传统方法、持仓/观察标的、个人经验、大盘/情绪/板块环境组织为稳定且节省 Token 的模型输入。
3. 使用可编辑 Markdown Prompt，为模型建立“A 股资深交易员、风险优先、证据驱动”的身份和分析流程。
4. 输出严格结构化结果，同时保留传统、大模型和融合三层结果，便于复盘与回测。
5. 大模型只提供分析与建议。交易信号是否下发仍由确定性规则、风控和人工确认控制。

已确认的统一策略定位：所有传统策略、LLM 分析、融合、评价和后续学习均服务于 **A 股短线趋势波段**，不把本系统扩展为长期价值投资、纯消息追涨或高频交易系统。具体预测周期、典型持仓天数和退出节奏仍需单独配置并通过回测确定。

## 2. 当前项目现状

### 2.1 已有复盘中心

当前复盘中心的主要入口为：

- `scripts/review_center_server.py`：本地 HTTP API、行情获取、个股分析和交易建议；
- `python/akquant/lwc/_template.py`：复盘页面和交易信号表格；
- `tests/test_review_center_signals.py`：现有选股、预测与操作触发测试；
- `.review_center_state.json` / `pools.json`：观察、持仓和模拟交易状态；
- `docs/zh/guide/visualization.md`：复盘中心使用说明。

现有数据源：

| 数据 | 当前来源 | 当前用途 |
| --- | --- | --- |
| A 股搜索 | 东方财富公开搜索接口 | 股票代码和名称搜索 |
| 实时报价 | 东方财富公开报价接口 | 现价、昨收、涨跌幅 |
| 日 K | 腾讯前复权日 K，失败后回退东方财富 | 个股技术分析和图表 |
| 大盘 | 东方财富报价接口 | 上证指数、创业板指数当日涨跌幅 |
| 本地票池 | JSON 状态文件 | 观察、持仓、模拟交易 |

当前实现已将行情缓存改为 180 秒，日 K 请求范围改为 360 个自然日。缓存只存在于进程内。

已确认的改造目标：

- 行情缓存统一调整为 **3 分钟（180 秒）**；强制刷新仅由明确的刷新动作触发；
- 日 K 数据源请求范围调整为 **最近 360 个自然日**，并保留数据时间戳、复权方式和实际返回交易日数量；
- 360 天是数据源请求窗口，不代表把全部原始 K 线发送给 LLM；Prompt 仍只传必要的近期紧凑 K 线、统计特征和事件标签；
- 回测读取历史快照，不使用 3 分钟实时缓存替代历史时点数据。

### 2.2 当前传统选股与趋势方法

当前分析不是 AKQuant 通用 ML 框架中的模型，而是直接写在复盘中心服务中的一套专用逻辑。

#### 特征

每个历史样本使用以下 8 个无未来数据特征：

1. 1 日收益；
2. 5 日收益；
3. 20 日收益；
4. `MA5 / MA20 - 1`；
5. `MA20 / MA60 - 1`；
6. 最近 10 日收益波动率；
7. 标准化 RSI14；
8. `5 日均量 / 20 日均量 - 1`。

#### 次日上涨概率

- 模型：`StandardScaler + LogisticRegression`；
- 标签：下一交易日收盘价高于当日收盘价；
- 类别权重：`balanced`；
- 最低日 K 数：90；
- 最多训练样本：360；
- 至少有效样本：30，且标签必须包含两类；
- 验证集：最后 `min(60, max(20, 样本数 / 5))` 个样本；
- 当前验证指标：Accuracy；
- 历史版本在模型不可用或依赖缺失时曾回退为 `0.5`；当前实现已改为概率 `null`，并使用 `insufficient_data`/`unavailable` 状态及原因区分“模型不可用”和真实中性。

已知不足：

- 单次按时间切分验证，尚未做滚动 Walk-Forward；
- 只报告 Accuracy，未报告 Brier Score、AUC、Precision/Recall 和概率校准；
- 每只股票独立训练，样本较少；
- 概率为“次日上涨”概率，不能直接解释为中期收益概率；
- 训练失败会回退到 0.5，页面当前未充分区分“真实中性”和“模型不可用”。改造后禁止用数值 `0.5` 表示不可用：真实中性必须是有效模型输出，不可用必须使用 `probability=null` 和明确状态/原因。

#### 选股评分

基础分为 50，当前规则为：

| 规则 | 分值 |
| --- | ---: |
| 20 日动量 × 150 | 截断到 `[-20, +20]` |
| 收盘价高于 MA20 | `+10`，否则 `-10` |
| MA20 高于 MA60 | `+8`，否则 `-8` |
| RSI14 在 `[45, 70]` | `+5` |
| RSI14 `>= 80` | `-6` |
| 量比相对 1 的变化 × 5 | 截断到 `[-5, +5]` |
| 最终分数 | 截断到 `[0, 100]` |

趋势定义：

- 多头排列：`close > MA20 > MA60`；
- 空头排列：`close < MA20 < MA60`；
- 其他：趋势混合；
- 趋势方向进一步分为上升、下降、偏强、偏弱、震荡。

#### 当前操作阈值

| 场景 | 当前条件 |
| --- | --- |
| 关注 | 评分 `>= 60` 且上涨概率 `>= 0.50` |
| 买入 | 评分 `>= 65`、上涨概率 `>= 0.54`、现价高于 MA20 |
| 强势买入 | 评分 `>= 72`、上涨概率 `>= 0.58`、`现价 > MA20 > MA60` |
| 加仓 | 持仓股评分 `>= 75`、上涨概率 `>= 0.60`、`现价 > MA20 > MA60` |
| 硬止损卖出 | 持仓收益 `<= -8%` |
| 趋势卖出 | 现价低于 MA60 且 20 日动量为负 |
| 模型卖出 | 上涨概率 `<= 0.40` 且现价低于 MA20 |

价格与仓位建议：

- 买入/加仓建议价：不高于现价的 MA5，MA5 不可用时参考 MA20；
- 建议数量：约占复盘初始资金 10%，按 100 股一手向下取整，最低一手；
- 止损参考：`现价 - max(2 × ATR14, 现价 × 6%)`；
- 止盈参考：`现价 + max(3 × ATR14, 现价 × 10%)`；
- 压力/支撑：从 MA5、MA20、MA60、20 日高低点中选择最近的有效价位。

这些阈值目前硬编码在 `review_center_server.py` 中，尚不能通过配置编辑。

```text
行情/票池/回测结果/市场数据/妙想只读数据
                    │
                    ▼
          本地特征与传统信号计算
                    │
       ┌────────────┴────────────┐
       ▼                         ▼
传统结果快照                 Prompt 输入构建器
       │                  ┌──────┼────────┐
       │                  ▼      ▼        ▼
       │              市场快照 经验检索  个股压缩数据
       │                  └──────┼────────┘
       │                         ▼
       │                    LLM Provider
       │                         │
       └────────────┬────────────┘
                    ▼
              确定性融合与风控
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
        页面展示   审计存档   可选信号草稿
```

### 3.1 三层结果必须同时保留

#### A. 传统层

记录当前策略 ID、版本、输入特征、评分、概率、趋势、阈值命中和风险价位。它是可重复、可回测的基线。

#### B. 大模型层

记录模型对以下问题的独立判断：

- 技术结构是否支持传统信号；
- 市场和板块是否提供顺风或逆风环境；
- 当前持仓的盈亏、成本和风险是否适合执行；
- 个人经验规则中哪些被命中；
- 存在哪些反证、缺失数据和不确定性。

大模型层不得直接生成可下发订单。它只能生成结构化分析建议。

#### C. 融合层

由本地确定性代码完成：

- 比较传统结果和大模型结果；
- 处理冲突、低置信度、数据过期和缺失；
- 执行硬风控否决；
- 生成唯一的最终评分、概率口径、趋势、操作建议和条件化交易计划。

这样可以在复盘时回答：传统模型错了、大模型错了、市场状态判断错了，还是融合规则错了。

### 3.2 大模型不能覆盖的硬约束

以下规则应由确定性程序处理，大模型无权绕过：

- 数据时间戳过期或关键字段缺失；
- 停牌、涨跌停、最小交易单位、T+1 和可用持仓；
- 账户级/策略级风控；
- 明确的硬止损和最大仓位限制；
- 信号幂等、订单审计和人工确认；
- 历史回测的时间点数据约束。

### 3.3 每日观测、反馈与训练闭环

模型不会因为每天被调用就自动记住过去。要实现“持续每日分析后逐步进化”，必须由系统显式保存历史并在结果成熟后反馈：

```text
每日候选与持仓
      │
      ▼
冻结当日输入、传统结果、LLM 结果、融合信号与版本
      │
      ▼
等待预设预测周期结束，生成真实标签与交易反馈
      │
      ├──► 评估传统/LLM/融合表现
      ├──► 更新概率校准器与轻量融合模型
      └──► 生成待审核经验案例，不自动篡改硬规则
                       │
                       ▼
              Walk-Forward 样本外验证
                       │
                       ▼
              通过门槛后版本化发布/可回滚
```

首选演进方式不是立即微调通用大模型，而是：

1. 建立不可变的“预测时点快照”，解决回测和数据泄漏问题；
2. 将实际涨跌、收益、MAE/MFE、是否触发止损/止盈、持仓天数和人工反馈回填为标签；
3. 用校准器或轻量监督学习模型学习传统、LLM、市场和板块结果的融合关系；
4. 把经过验证的成功/失败案例压缩成可检索经验，供后续 Prompt 引用；
5. 达到足够样本量后再评估微调，且训练集、验证集和测试集必须按时间隔离。

任何自动学习结果均不得直接覆盖线上冠军版本。采用 `champion/challenger`、版本号、样本外门槛和一键回滚；人工评价可作为辅助标签，但不能替代真实市场结果。

## 4. 模型配置方案

### 4.1 配置目标

用户要求的 `url`、`sk`、`model` 均可配置。首个启用项已确定为用户提供的 OpenAI 兼容服务。为兼顾安全，配置层同时支持：

- `sk` / `api_key`：允许直接写入仅限本机的配置文件；
- `api_key_env`：配置环境变量名，推荐方式；
- `${ENV_NAME}`：在配置字符串中引用环境变量。

开发时计划使用 OpenAI Python SDK 作为兼容客户端，并通过 Provider Adapter 处理不同 API 风格。`https://www.codexapis.com/v1` 不是 OpenAI 官方 API 域名，因此文档和审计中仍标记为 `openai_compatible`。用户已确认该服务及模型支持 Responses API、JSON Schema、流式输出、usage 和缓存；开发时不再探测选择 API 风格，但仍需执行最小健康检查和响应字段兼容性测试，避免配置、鉴权或服务版本变化造成静默失败。

### 4.3 Provider 兼容性

| Provider | 推荐 API 风格 | 说明 |
| --- | --- | --- |
| 首选：CodexAPIs | Responses API | URL 为 `https://www.codexapis.com/v1`，模型字符串为 `gpt-5.6-luna`；用户已确认支持 JSON Schema、流式输出、usage 和缓存；属于 OpenAI 兼容服务，不宣称为 OpenAI 官方服务 |

模型名不在业务代码中写死。首选 Provider 的模型配置为 `gpt-5.6-luna`，相关能力已由用户确认；启动健康检查仍需验证鉴权成功、模型可调用，以及 Responses、JSON Schema、流式事件、usage 和缓存字段能被当前客户端正确解析。

## 5. 模型输入设计

每次分析包含四类业务输入，但不会把原始全部数据直接塞进 Prompt。

### 5.1 传统方法与个股判断

输入内容：

- 策略 ID 和版本；
- 当前评分及分项贡献；
- 次日和未来 5 个交易日的上涨概率、各自验证指标、训练样本数和模型有效状态；
- MA、RSI、ATR、动量、量比、支撑、压力；
- 当前传统操作建议及具体触发条件；
- 当前所有阈值版本。

必须同时传递“数值”和“由哪条规则得出”，避免模型只看到结论。

### 5.2 持仓、观察标的和行情

持仓输入：

- 代码、名称、成本、数量、现价、持仓收益、仓位占比；
- 可用数量、T+1 状态等交易约束（数据源可提供时）；
- 最近技术摘要；
- 压缩后的近期 K 线和量价异常事件。

观察标的输入：

- 加入观察时的价格和备注；
- 当前相对收益；
- 传统排名、技术摘要；
- 压缩后的近期 K 线和量价异常事件。

日 K 数据源按已确认方案请求最近 360 个自然日，但每次只向 LLM 传最近 **10 根日 K**。系统按实际分析需要选择分钟 K 周期，覆盖不超过 **3 个交易日**，每个交易日从 `09:30` 开盘截取到刷新时点，用于日线收盘后复核日内量价结构。推荐本地先计算特征，只按配置传：

- 最近 10 根日 K 的紧凑数组；
- 按实际需要选择周期、最多覆盖 3 个交易日的分钟 K 紧凑数组及日内事件摘要；
- 1/5/10/20/60 日收益和波动；
- 均线、ATR、RSI、量比；
- 放量突破、缩量回踩、跳空、长上影、破位等本地事件标签。

LLM 每次只分析用户在复盘中心点选的票池/标的，不自动扫描全部票池。日 K 传输数量已确定为 10 根；分钟 K 周期由本地上下文构建器根据分析需要、数据源能力和 Token 预算选择，最多覆盖 3 个交易日，并记录本次实际周期与范围。周期不能由 LLM 自主选择。这与数据源固定请求 360 天是独立配置。

### 5.3 个人交易知识和经验

推荐使用“Markdown 为事实源 + 本地索引为缓存”的方式：

- 少量、每次必须遵守的规则：压缩后作为固定 Prompt 前缀；
- 按市场、板块、形态、持仓状态分类的经验：按需检索后注入；
- 历史案例：只检索最相关的少量案例摘要；
- SQLite FTS5 或简单标签索引：负责查找，不是知识事实源；
- 当知识量显著增长、关键词检索不足时，再评估向量检索和混合 RAG。

数据库本身不会节省 Token，只有“只取相关片段”才会节省 Token。当前阶段不推荐微调：

- 个人知识经常修改，文档/RAG 更容易更新；
- 微调不适合保存频繁变化的行情和交易规则；
- 微调会降低可追溯性，且需要额外样本、评估和费用。

已整理的实际经验见 [A 股短线趋势波段个人交易知识库](../advanced/llm_trade_personal_knowledge.md)，新增卡片格式见 [个人交易知识模板](../advanced/llm_trade_knowledge_template.md)。

### 5.4 大盘环境、市场情绪和板块强度

当前项目只有上证和创业板当日涨跌幅，不足以支撑完整环境判断。目标输入建议包括：

#### 大盘环境

- 上证、深证、创业板、沪深 300、中证 1000 等核心指数；
- 1/5/20/60 日收益、趋势、波动和成交额；
- 指数相对 MA20/MA60 的位置；
- 风格：大盘/小盘、价值/成长、权重/题材。

#### 市场情绪

- 上涨/下跌家数和涨跌比；
- 涨停/跌停家数；
- 炸板率、连板高度、赚钱效应；
- 全市场成交额及相对近期均值；
- 风险事件和重要政策摘要。

#### 板块强度

- 个股所属行业和概念；
- 板块 1/5/20 日相对强弱；
- 板块涨跌家数、成交额、资金流；
- 个股在板块中的排名；
- 板块催化和风险事件。

这些字段必须逐项标记来源、时间戳和是否可用。缺失时不得由模型自行补全。

## 7. Prompt 设计

Prompt 拆为四部分：

1. `system`：身份、风险边界、禁止事项；
2. `analysis_protocol`：固定分析步骤；
3. `output_contract`：严格输出结构；
4. `dynamic_context`：市场、板块、个股、传统结果和检索到的经验。

固定内容放在前缀，动态内容放在末尾，便于供应商 Prompt Cache 命中。

完整草案见 [A 股资深交易员 Prompt 模板](../advanced/llm_trade_prompt_template.md)。

核心要求：

- 所有分析以 A 股短线趋势波段为统一策略语境；
- 只使用提供的数据；
- 先检查时间戳和数据质量；
- 区分事实、传统模型结果、经验规则和模型推断；
- 充分区分“有效模型判断为中性”和“模型/数据不可用”；
- 必须给出反证和失效条件；
- 不把 LLM 自身概率描述成已校准统计概率；
- 不直接输出下单命令；
- 输出必须通过 JSON Schema 校验。

## 8. 传统结果与大模型结果的统一

### 8.1 不建议直接覆盖或简单平均

传统模型概率和大模型主观概率不是同一种统计量：

- 传统概率来自当前个股历史特征上的 Logistic Regression；
- 大模型概率来自文本、市场和经验的主观综合判断；
- 两者未经过联合校准时，直接平均会产生虚假的精确性。

### 8.2 推荐的分阶段融合

#### 首版：直接规则修正模式

- 用户已明确不采用影子模式，首版测试结果直接进入复盘中心融合信号；
- 传统评分和概率仍是量化基线；
- 大模型仅在数据质量和置信度达标时，对最终等级做有限修正；
- 大模型可以降低风险等级或要求等待确认；
- 大模型不得取消硬止损、突破最大仓位或绕过交易规则。

“直接测试使用”仅表示融合结果直接影响复盘中心交易信号，不表示自动实盘下单。模型调用失败时立即降级到传统基线，并在页面明确显示降级原因。

#### 后续：校准融合模式

只有积累足够样本并完成 Walk-Forward 后，才允许：

- 学习传统结果、大模型结果、市场状态和板块强度的融合权重；
- 对最终上涨概率做概率校准；
- 比较融合前后 Brier Score、AUC、Precision/Recall、收益、回撤和稳定性；
- 只有新版本在严格 Walk-Forward 样本外评价中达到发布门槛，才替换当前线上版本。

### 8.3 融合规则草案

首版采用可解释、可约束的固定权重，后续再用样本外数据训练替换。初始参数建议并写入版本化配置：

- 传统结果基准权重 `0.70`；
- LLM 最大权重 `0.30`；实际权重按 LLM 置信度和输入数据质量向下缩放；
- 相对传统评分，LLM 单独造成的最终评分修正最多 `±10` 分；
- 相对传统概率，规则融合造成的概率修正最多 `±0.08`；
- 仅由 LLM 引起的操作等级变化最多一级，例如“观察 → 等待买入”，不能直接“观察 → 强势买入”；
- 市场、板块和硬风控作为门控/否决条件，不与模型分数机械加权；硬止损、数据无效和交易约束优先级最高。

有效权重建议按下式计算：

```text
llm_effective_weight = 0.30 × llm_confidence × data_quality_factor
traditional_weight = 1 - llm_effective_weight
raw_score = traditional_weight × traditional_score
          + llm_effective_weight × llm_score
final_score = clip(raw_score, traditional_score - 10, traditional_score + 10)
```

其中 `llm_confidence` 和 `data_quality_factor` 均为 `[0, 1]`。LLM 不可用时权重为 0；LLM 有效中性不等于不可用，仍保留少量中性修正信息。

概率按两个周期分别处理，绝不平均不同周期：

```text
P_final(h) = clip(
  P_traditional(h) + llm_effective_weight × (P_llm(h) - P_traditional(h)),
  P_traditional(h) - 0.08,
  P_traditional(h) + 0.08
)
```

`h` 分别为次日和未来 5 个交易日。开发时需要为 5 日周期建立独立标签与传统概率模型；在 5 日传统模型尚未有效前，5 日融合概率必须为 `null`，可以单独显示 LLM 主观判断，但不得伪装成已融合、已校准概率。

确定性执行顺序：

```text
if 数据无效或过期:
    assessment_status = insufficient_data
    最终动作 = null
elif 命中硬止损或账户硬风控:
    最终动作 = 止损/清仓
else:
    传统结果 = 基线
    大模型结果 = 按置信度、质量和最大幅度进行有限修正
    板块/大盘 = 风险门控
    冲突较大时 = 降低置信度并转为等待确认
```

初始 `70/30`、`±10` 和 `±0.08` 是首版测试参数，不宣称为最优值。积累足够每日样本后，使用带正则约束的简单 Meta Model 在 Walk-Forward 中学习权重，以 Brier Score、AUC、回撤、收益和换手共同决定是否发布；训练结果仍受最大仓位、硬止损和操作等级约束。

建议把冲突分为：

- `none`：方向一致；
- `minor`：方向一致但入场时机或仓位不同；
- `major`：一方买入、一方观望/减仓；
- `critical`：一方买入、另一方止损/清仓，或命中硬风险。

### 8.4 最终输出

最终结果必须同时展示：

- 传统评分、传统上涨概率、传统趋势和传统操作；
- 大模型评分、主观概率、置信度、市场/板块判断和建议；
- 最终评分、最终概率口径、最终趋势、冲突等级；
- 买入、加仓、持有、减仓、卖出、止损、清仓的条件化计划；
- 价格区间、触发走势、失效条件、仓位上限和时间范围；
- 数据质量、风险提示、证据和经验引用；
- Provider、模型、Prompt、知识库和策略版本。

最终 `fusion` 结果是复盘中心“交易信号”区域的唯一主信号来源；传统与 LLM 原始结果保留为解释和审计列，不直接产生第二套互相冲突的页面操作。

交易信号区域改造原则：

- API/存档使用稳定 Schema，主表草案中的全部列默认显示，页面允许调整顺序和宽度；
- 桌面端主表默认只展示融合结果和关键短线字段，传统/LLM 分项、更多证据和完整动作计划在行展开详情中显示；
- 宽度不足时允许横向滚动或切换为摘要卡片，不通过删除风险字段强行压缩；
- 空值显示 `—`，真实中性显示“中性”，模型不可用显示“不可用 + 原因”，三者不得混淆；
- 表头已按下表确认并全部默认显示；最小宽度和区域位置在开发时结合当前复盘中心实际布局验证，不在方案阶段猜固定像素。

主表表头草案：

| 股票 | 池/持仓 | 现价/持仓收益 | 短线趋势 | 次日概率 | 5日概率 | 评分 | 融合信号 | 操作建议 | 大盘/板块 | 触发价格 | 建议仓位%/数量 | 卖出比例/止损 | 质量/冲突 | 更新时间 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

行展开详情显示评分分项、概率评价指标、支持/反对证据、买入/加仓/持有/减仓/卖出/止损/清仓计划、仓位约束、历史相似案例和全部版本信息。上述主表表头全部默认可见；具体列宽和响应式排列在页面实现时按现有复盘中心空间调整。

退出动作按用户确认的业务含义处理：

| 动作 | 仓位处理 | 适用含义 |
| --- | --- | --- |
| 减仓 | 部分卖出 | 主动降低风险或锁定部分利润，不代表交易逻辑完全失效 |
| 卖出 | 允许部分卖出 | 趋势转弱、到达目标或条件触发后的计划退出；必须输出明确卖出比例/数量 |
| 止损 | 卖出全部可用持仓 | 价格或交易逻辑触发硬止损，不能被 LLM 否决 |
| 清仓 | 卖出全部可用持仓 | 非止损原因但持仓逻辑完全失效、风险状态禁止继续持有或用户要求全部退出 |

止损和清仓的目标退出比例固定为 `100%` 的可用持仓。普通卖出不设固定比例，由模型根据实际持仓规模、仓位占比、浮盈亏、趋势破坏程度、市场/板块风险、流动性和可用持仓推荐 `target_exit_ratio`；本地融合与风控再按可用数量、100 股交易单位和仓位限制校正。证据不足时转为“等待人工确认”，不能生成含糊的部分卖出信号。

止损和清仓允许同时作为有效条件计划存在：二者分别保存触发条件，当前操作只执行已触发且优先级最高的一项，避免重复退出。

买入、加仓、减仓、卖出、止损和清仓都必须同时给出账户百分比和股票数量；股票数量按可用资金/持仓、价格和 A 股 100 股交易单位向下取整。

价格区间采用 `short_swing_price_v1`：回踩围绕 MA5、MA20 或最近突破支撑，突破买入设置 `0.10×ATR14` 确认缓冲和最多 `min(0.50×ATR14, 1.5%)` 的追价空间；目标卖出围绕压力位使用 `min(0.30×ATR14, 1.0%)` 容差；止损综合结构破位缓冲、ATR 波动止损和现有 8% 硬止损。详细公式由[统一输出结构](../advanced/llm_trade_output_schema.md)定义，参数全部版本化并通过 Walk-Forward 调整。

完整字段见 [统一输出结构](../advanced/llm_trade_output_schema.md)。

## 9. Token 与缓存策略

### 9.1 固定前缀

固定且可编辑的内容：

- 角色身份；
- 分析流程；
- 风险约束；
- 输出 Schema；
- 少量 `always_apply` 经验规则。

固定前缀必须保持字节级稳定，并用版本号控制。动态数据全部放在其后。

OpenAI 官方 Prompt Caching 对受支持模型默认启用，并依赖相同前缀；Structured Outputs Schema 也会影响缓存匹配。DeepSeek 也公开了上下文缓存机制，但不同供应商的计费和命中规则不一致，因此系统不能只依赖供应商缓存。

### 9.2 本地缓存

计划缓存以下对象：

- 市场环境快照；
- 板块强度快照；
- 个股特征摘要；
- 经验检索结果；
- 编译后的固定 Prompt；
- 模型响应。

已确认行情类缓存 TTL 为 **180 秒**，包括实时个股报价、指数快照及由同一时点行情计算的短生命周期摘要。日 K 请求窗口固定为最近 **360 个自然日**；日 K 缓存键必须包含标的、周期、复权方式、起止日期和数据源。板块、经验检索、Prompt 和模型响应使用各自 TTL/版本键，不能一律套用 180 秒。

响应缓存键应至少包含：

```text
provider + model + prompt_version + schema_version + knowledge_version
+ traditional_strategy_version + symbol + data_as_of + normalized_input_hash
```

除已经确认的行情 180 秒外，其余缓存有效期按日线/盘中场景配置，并记录命中时间和数据 `as_of`。手动强制刷新应绕过行情缓存，但仍不得绕过供应商限流保护。

### 9.3 输入压缩

- 原始数值用紧凑 JSON，不重复中文字段解释；
- 市场快照一次生成，多只股票复用；
- 板块快照按板块缓存；
- 个人经验只检索相关卡片；
- 先用本地算法发现异常，再传异常标签；
- 不传页面展示文本、重复原因和完整历史报告；
- 只在大模型结论变化或用户展开详情时生成长解释。

### 9.4 调用分层

采用用户触发的两级调用：

1. 本地预处理：对用户点选票池计算传统特征、市场/板块摘要和风险门控；
2. LLM 深度分析：只对本次用户明确点选的标的调用，并生成融合信号。

批量上限按 Token 和服务限流实测后配置；无论上限如何，系统不得把未点选标的自动加入付费调用。

### 9.5 保存期限与历史注入

本地保存历史结果本身不会增加下一次模型调用的 Token；只有把历史内容再次放入 Prompt 才会产生输入 Token。因此保存和注入必须分开设计：

- 结构化观测、最终信号、到期标签、评价指标、版本号和哈希体积较小，是训练/回测依据，应长期保留；
- 完整 Prompt、原始响应和大段外部资料按用户规则分级保存：普通记录 30 天，超长记录 7 天；
- “超长”的 Token/字节阈值在真实调用统计后确定并写入配置，方案阶段不猜数值；
- 下次调用不加载全部历史，只检索少量相关规则、相似案例摘要和近期必要反馈；
- 原始内容过期后保留结构化摘要、引用 ID、哈希、Token 用量和评价标签，以支持审计与训练。

这样既满足 30/7 天原文留存策略，也不会因积累历史而让每次 Prompt 线性增长。

## 10. 输出校验与失败降级

传统模型、LLM 和融合层都必须分别输出 `assessment_status`，至少区分：

- `valid_directional`：模型有效且给出方向性判断；
- `valid_neutral`：模型有效，概率/证据确实接近中性；
- `insufficient_data`：输入样本或关键字段不足；
- `unavailable`：依赖缺失、调用失败、超时、限流、余额不足或训练异常；
- `degraded`：部分数据/模型不可用，但系统使用明确记录的降级路径生成结果。

`valid_neutral` 必须同时满足模型有效、评价流程有效且结果落入经配置定义的中性区间。`unavailable` / `insufficient_data` 的概率字段必须为 `null`，不得再回填 `0.5`。融合层降级到传统结果时，应显示“LLM 不可用，采用传统基线”，而不是显示“LLM 中性”。

优先使用供应商支持的 Structured Outputs / JSON Schema。若 Provider 不支持：

1. 要求 JSON 模式；
2. 本地 Pydantic 校验；
3. 只允许一次格式修复重试；
4. 仍失败则保留原始响应并回退到传统结果；
5. 页面明确显示“LLM 分析不可用”，不能伪装成中性结论。

以下情况必须降级：

- 模型超时、限流或余额不足；
- Schema 不合法；
- 关键数据时间不一致；
- 妙想或外部数据不可用；
- 模型输出引用了输入中不存在的事实；
- 置信度过低或冲突为 `critical`。

## 11. 回测与评估方案

### 11.1 避免未来数据

历史回测只能使用当时可获得的数据：

- K 线按回测时点截断；
- 新闻、公告和板块事件必须有历史快照；
- 禁止用当前妙想检索结果回答历史日期问题，除非接口能够严格按发布时间过滤且已验证；
- Prompt、模型名、Provider、知识版本和输出必须冻结并存档。

### 11.2 评估维度

预测质量：

- Accuracy、Precision、Recall、AUC；
- Brier Score 和概率校准曲线；
- 不同市场状态、板块、持仓状态下的分组表现。

这些指标对本系统有用，计划纳入报告，但必须结合样本数、正负样本占比和时间窗口解释：

| 指标 | 在本系统中的用途 | 主要注意事项 |
| --- | --- | --- |
| Brier Score | 衡量概率与真实结果的平方误差，判断“60% 上涨概率”是否真的比“50%”更可靠；越低越好 | 受事件基准率影响，需同时报告基准模型和分组结果 |
| AUC | 衡量模型把上涨样本排在下跌样本前面的能力，适合检验选股排序；越高越好 | 不反映概率是否准确，也不直接代表策略赚钱 |
| Precision | 在发出买入/强势信号的样本中，实际达到正类标签的比例，反映信号纯度 | 依赖信号阈值和正类定义，不能脱离交易次数解释 |
| Recall | 所有实际正类机会中，被模型捕捉到的比例，反映漏掉多少机会 | 提高 Recall 可能牺牲 Precision，需结合换手和成本 |
| 概率校准 | 比较预测概率分桶与实际发生率，使最终概率可用于风险分层、仓位和阈值 | 样本少时曲线不稳定，只能在样本外数据上拟合/评价 |

报告同时给出 `sample_count`、正类比例、评价起止日期、预测周期、阈值和置信区间/稳定性提示。标签单一或样本不足时，AUC、Precision/Recall 等显示“不可计算”，不能填 0。指标用于比较模型版本，不能代替收益、回撤、滑点和风险评价。

交易质量：

- 收益、最大回撤、夏普、Calmar；
- 胜率、盈亏比、交易次数；
- MAE/MFE、止损效率、持仓期；
- 换手、滑点和手续费敏感性。

融合增益：

- 传统基线；
- 传统 + 市场门控；
- 传统 + LLM 影子建议；
- 传统 + LLM 规则修正；
- 完整融合。

必须通过 Walk-Forward 或严格样本外方式比较，不能只看同一历史区间内的最优结果。

### 11.3 每日分析记录与标签回填

每天对“当日策略实际纳入分析范围”的全部标的保存一条不可变观测，不只保存最终买入股，避免选择偏差。至少记录：

- 交易日、分析时点、标的和票池状态；
- 360 天请求窗口内在当时可见的行情摘要及数据哈希；
- 传统特征、评分、概率、有效状态、阈值和策略版本；
- LLM 输入哈希、结构化输出、有效状态、模型/Prompt/知识版本；
- 大盘、市场情绪、板块强度和妙想引用快照；
- 融合结果、最终交易信号、触发价、失效价和风险否决；
- 用户是否采纳、实际模拟交易及人工复盘标签。

预测周期结束后由独立任务回填真实结果。次日主标签为“下一交易日收盘价高于当前收盘价”；5 日主标签为“第 5 个交易日收盘价高于当前收盘价”。同时在 `t+1` 至 `t+5` 路径内记录收益、MAE、MFE、最大回撤、是否触发止损、首次触发时间、信号后最佳/最差路径和实际交易结果。主分类标签与路径风险标签分别存储，不能用良好的第 5 日收盘结果掩盖期间已经触发的止损。标签定义必须版本化，不能事后为了提高指标修改。

### 11.4 可训练演进方案

传统方法与 LLM 方法可以支撑逐日积累和训练，但分为不同层次：

1. **传统模型再训练**：按滚动时间窗或扩展时间窗训练，并使用 Walk-Forward 生成严格样本外概率；
2. **概率校准**：对传统概率及后续融合概率使用 Platt/Isotonic 等校准方法，具体方法按样本量和样本外表现选择；
3. **融合模型训练**：以传统分数/概率、LLM 结构化评分、市场状态、板块强度、数据质量和冲突信息作为特征，训练轻量可解释的 Meta Model；
4. **经验库演进**：把成熟结果整理为成功、失败和反例案例，经规则或人工审核后进入检索库；
5. **大模型微调**：仅在积累足够高质量、授权可用且结构一致的数据后评估，不作为首版依赖。

训练与线上推理隔离。每日可以生成候选模型，但只有达到最小样本、完成时间外验证，并在预测指标和交易指标上通过发布门槛后才能升级；否则继续使用当前冠军版本。所有版本必须可重放、可比较、可回滚。

| 价格区间 | 使用 `short_swing_price_v1`：结构位 + ATR 容差 + 突破缓冲 + 最大追价限制 |
| 仓位输出 | 账户百分比和按 100 股取整的股票数量两者都输出 |
| 妙想账号 | 允许登录用户账号现场核验 Key、点数、赠送、计费和条款 |
| 妙想权限 | 允许审核后的只读工具；自选管理仅允许用户明确触发；禁用模拟交易及真实交易写工具 |
| 个人经验 | 不包含敏感信息，允许发送给已配置的云模型 |
| 离线模型 | 不需要本地模型或离线隐私备选 |
| 保存期限 | 普通原始 Prompt/响应保存 30 天，超长记录保存 7 天；紧凑结构化训练记录长期保留 |
| 页面展示 | 默认展示融合结果；主表草案全部表头显示，并单列评分和操作建议；展开后显示传统、LLM、融合三层明细 |

### 15.2 对原剩余事项的确认与处理

1. **模型能力已确认**：`codexapis.com` 的 `gpt-5.6-luna` 使用 Responses API，并支持 JSON Schema、流式输出、usage 和缓存。开发时只做健康检查与字段兼容性测试，不再在 Responses/Chat Completions 之间自动选择。
2. **K 线范围已确认**：传给 LLM 的日 K 为最近 10 根；分钟 K 周期根据实际分析需要自适应，每日从 `09:30` 到刷新时点，覆盖不超过 3 个交易日。周期由本地程序结合数据源能力和 Token 预算选择并审计，不预先固定，也不由 LLM 决定。
3. **卖出比例已确定为动态推荐**：普通卖出根据实际仓位和风险输出明确比例，由本地交易约束校正；止损和清仓固定退出 100% 可用持仓。
4. **标签已确认**：次日标签为下一交易日收盘上涨；5 日标签为第 5 个交易日收盘上涨，并同时记录期间 MAE、MFE、最大回撤和止损路径。
5. **原始记录分档阈值仍需运行数据**：进入 7 天档位的 Token/字节阈值，根据首批真实调用分布确定；未获得分布前不伪造固定阈值。
6. **自选工具仍需官方清单**：实际工具名、参数和权限以官方 `tools/list` 为准，首次写入前由用户确认目标自选组。
7. **模型发布门槛仍需历史基准**：最小样本量、评价窗口和发布门槛在首批数据积累后确定，不能在没有数据时声称某个阈值最优。

至此，当前开发计划没有必须由用户继续补充的配置项。第 5～7 项属于必须在真实调用、官方工具清单或历史样本出现后才能完成的运行期验证，不阻塞基础框架开发。
